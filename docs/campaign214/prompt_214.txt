## Stage 214.1 — Screenshot and Framebuffer Forensic Audit

Investigate the identical hashes reported for:

- `screenshot_02_counter_app_launched.bmp`
- `screenshot_03_counter_app_incremented.bmp`
- `screenshot_04_return_to_shell.bmp`

## Stage 214.3 — Headless and Actual Windows Presentation Modes

2. Actual Windows desktop window presentation for interactive use.

For desktop mode:

- Create a real Windows top-level window.
- Display the composed guest framebuffer.
- Handle resizing, DPI scaling, window close, and orderly shutdown.
- Ensure the displayed content originates from the guest-owned surfaces.
- Avoid substituting a host-drawn mock interface for guest output.

Acceptance: automated headless tests still pass, and a real Windows window can display the guest shell and its applications.

## Stage 214.4 — Frame and Presentation Accounting

Define precise counters for:

- Guest surface presents.
- Damage-triggered compositor passes.
- Composed frames.
- Host presentation attempts.
- Successfully presented host frames.
- Repeated frames.
- Dropped frames.
- Vsync/deadline events.

Investigate the Campaign 213 difference between five compositor passes and seven host frames.

Acceptance: counters have unambiguous definitions and deterministic tests cover repeated, dropped, and newly composed frames.

## Stage 214.5 — Darwin ABI and Custom Extension Boundary

Audit the Category C syscall IDs 500–506.

- Preserve DarwinStrict syscall handling.
- Keep WinIOS-specific extension IDs in a clearly versioned namespace.
- Document register arguments, return values, errors, pointer validation, and ABI version.

- Prevent extension calls from being misidentified as standard Darwin syscalls.
- Add unknown-ID and wrong-ABI negative tests.

Acceptance: no ABI ambiguity or accidental collision with existing Darwin syscall behavior.

## Stage 214.12 — Guest UI Resource and Theme Management
