# Cross-Core Interrupt Architecture & GICv3 Routing

## 1. Architectural Scope

In an ARMv8-A multicore system with GICv3 (Generic Interrupt Controller v3), interrupts are partitioned into distinct categories with dedicated distribution semantics:
- **SGIs (Software Generated Interrupts)**: INTIDs 0–15. Private to each core redistributor; used for Inter-Processor Interrupts (IPIs) triggered via `ICC_SGI1R_EL1`.
- **PPIs (Private Peripheral Interrupts)**: INTIDs 16–31. Private to each core redistributor (e.g. Virtual Timer INTID 27, Physical Timer INTID 30).
- **SPIs (Shared Peripheral Interrupts)**: INTIDs 32–1019. Shared distributor routing interrupts from system peripherals to one or more target cores based on affinity.

The `SmpInterruptRouter` subsystem (`src/cpu/smp_interrupt_router.h`, `src/cpu/smp_interrupt_router.cpp`) provides deterministic cross-core interrupt management.

---

## 2. Request vs. Delivery Phase Separation

A fundamental challenge in multi-core emulation is that asynchronous interrupts occurring mid-quantum on one core could unpredictably preempt another core if delivered immediately.

To guarantee determinism, `SmpInterruptRouter` strictly separates the **Request Phase** from the **Delivery Phase**:

```
[Virtual Core A]
       |
       | 1. request_interrupt(target_core=B, intid=45, priority=0x80)
       v
+-------------------------------------------------------------+
|                     SmpInterruptRouter                      |
|                                                             |
|   Pending Queues:                                           |
|   Core 0: [ FIFO Queue of Pending Interrupts ]              |
|   Core 1: [ Req 1: INTID 45 ] -> [ Req 2: INTID 7 (SGI) ]   |
|   Core 2: [ Empty ]                                         |
+-------------------------------------------------------------+
       |
       | 2. Scheduler advances to Core B boundary
       v
[Virtual Core B Execution Boundary]
       |
       | 3. router.deliver_next(target_core=B, cpuB, gic)
       v
[CPU B Architectural Exception Entry (raise_asynchronous_exception)]
```

### Deterministic Principles:
1. **Queued at Request**: When Core A triggers an SGI or an external device asserts an SPI, an `InterruptRequest` is pushed to the target core's queue. The target core's current architectural state is untouched until its designated boundary.
2. **Monotonic Request Ordering**: Requests receive a monotonically increasing sequence ID `request_sequence`.
3. **Deterministic FIFO Delivery**: Requests targeting a core are dequeued and delivered in exact FIFO order.
4. **Quiescent Wakeup**: If the target core is in `WaitingForInterrupt` (WFI), the presence of a pending request awakens the core to `Runnable`.

## 3. SGI Multicast Routing

Software-Generated Interrupts are generated by writing to system register `ICC_SGI1R_EL1` with a target core affinity mask:
```cpp
void SmpInterruptRouter::request_sgi(std::size_t source_core, std::uint32_t target_core_mask,
                                     std::uint32_t sgi_intid, std::uint8_t priority);
```
- Core mask bits correspond to virtual core IDs ($0 \le \text{core} < 32$).
- For each bit asserted in `target_core_mask`, an SGI request is queued into that specific core's queue.
- Sanity masking enforces $0 \le \text{sgi\_intid} \le 15$.

---

## 4. Telemetry Accounting

The router tracks:
- `sgi_count`: Total Software Generated Interrupts requested.
- `ppi_count`: Total Private Peripheral Interrupts requested.
- `spi_count`: Total Shared Peripheral Interrupts requested.
- `total_requested`: Total interrupt requests enqueued.
- `total_delivered`: Total interrupt requests delivered to CPU cores.
