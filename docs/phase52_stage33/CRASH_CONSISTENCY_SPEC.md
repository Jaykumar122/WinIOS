# WinIOS — Crash Consistency Specification
## Multi-Core Recording Persistence & Failure Recovery Semantics

---

## 1. Overview & Threat Model

In deterministic multi-core virtualization systems, recordings comprise interleaved execution events across virtual CPUs and external inputs (MMIO, DMA, interrupts). The persistence subsystem must guarantee:
1. **Crash Invariance:** A sudden host abort or system crash at any instruction or microsecond must never produce an unrecoverable corrupted recording that masquerades as valid.
2. **Deterministic Bound:** The recovered boundary must correspond to a valid system-wide quiescent state (a closed scheduling quantum and fully completed DMA operation).
3. **Zero Phantom State:** Incomplete DMA writes or unfinished CPU quantums must never be partially replayed.

---

## 2. Recording Lifecycle State Machine

A recording file transitions through the following lifecycle states:

```
    [Create File]
          |
          v
    +-------------+
    | HeaderOnly  |
    +------+------+
           |  First block written
           v
    +-----------------+
    | RecordingActive | <------+
    +--------+--------+        |
             |                 | Write next block & sync
             | Interrupted     |
             v                 |
    +--------------------+     |
    | CorruptOrAborted   |     |
    +--------+-----------+     |
             |                 |
             | Scanner salvage |
             v                 |
    +--------------------+     |
    | RecoverySalvaged   |     |
    +--------+-----------+     |
             |                 |
             | Normal exit     |
             v                 |
    +--------------------+     |
    |     Complete       |-----+
    +--------------------+
```

### State Definitions
- **`HeaderOnly` (`0x00`):** File created with valid header magic; no event blocks written yet.
- **`RecordingActive` (`0x01`):** Active recording session. Blocks are appended dynamically. Trailer is incomplete.
- **`Complete` (`0x02`):** Stream cleanly stopped via `stop_recording()`. Trailer finalized with valid event counts, final hash, and CRC.
- **`CorruptOrAborted` (`0x03`):** Stream detected with CRC failure, missing companion store, or truncated block. Cannot be directly replayed.
- **`RecoverySalvaged` (`0x04`):** Stream generated by `RecordingRecoveryScanner`. Trailing corrupt or open records removed; cleanly terminated at the last complete quantum. Replayable under standard capabilities.

---

## 3. Transactional Flush Boundaries

To balance high I/O throughput with crash resilience, SNDL v2 defines explicit flush points:
1. **Block Boundary Flush:** Every block (default 64 records or 64 KiB) is serialized with its own block header and CRC32C.
2. **DMA Completion Flush:** When a DMA transaction completes (`DmaTransferEnd`), the recorder ensures the corresponding companion payload is flushed to disk.
3. **Quantum Boundary Flush:** At the end of every virtual scheduling quantum (`QuantumEnd`), global retirement counters and per-core sequence numbers are strictly coherent.
